## Three-file installation

Add only the canonical runtime-v2 main caller, this ADR and the dated
[installation snapshot](../../governance/evidence/docs-source-successor/runtime-admission-source-successor-v2-installation.md).
The caller is generated by `callerWorkflowDefinition(S)` and verified by
`assertCallerWorkflow(bytes, S)` from the actual immutable source. It pins that
literal S, accepts no inputs or inherited secrets, and contains no local
checkout or command. The reusable workflow executes only source-owned code; its
defining source and target event remain separate identities.

This is the existing Central governance source-successor mechanism, with no new
framework, package, product boundary, authority registry or consumer Cohort
admission. All v1, v2 and v3 source, caller, ADR and evidence bytes remain
unchanged. After installation these three files are immutable under the
runtime-v2 ordinary route; later observations belong in separate evidence or PR
comments.

## Installation and permanent qualification

The finite source push certified PR389 while it was open. PR389 is now merged;
that historical run cannot certify the installation PR or be replayed as one.

Because main must never lack a source requirement, the temporary runtime-v2
requirement was exchanged for the installed quality v3 requirement before this
installation: v3 was re-added alongside runtime-v2, then runtime-v2 was
removed. The installation PR is admitted by the unchanged v3 ordinary route.

After the caller is installed, obtain real ordinary positive and protected-input
negative canaries through its immutable S. Retain the actual PR, base, head,
source, workflow, run and attempt and the decisive jobs and statuses. An
optional rejection proves rejection only. Add runtime-v2 while retaining v3 and
observe on that same negative head that runtime-v2 is required and mergeability
is blocked. Only after the genuine positive result and the required blocking
proof may v3 be removed for permanent enforcement. Do not merge a negative
canary.

## Rollback and limits

On failure stop and retain or re-add the previous requirement before removing
the new one, with complete owner readbacks and all unrelated fields preserved.
Do not unlock, update or delete any immutable source, historical tuple or
accepted installation snapshot. File rollback requires a separately reviewed
normal PR.

The qualification canaries on the source-defined refs prove the source's
accepting and rejecting behavior on exact heads. They are not installed-main
canaries; those and the permanent cutover remain pending in this snapshot.
