## Preserved ordinary behavior

Only that exact finite target may replace the reviewed protected inputs.
Every other request executes the real frozen v2 gate, including its finite
PR369 history and real v1 ordinary/dependency/historical routes. V1/v2 sources,
callers, installation records and accepted ADR bytes are preserved. V3's three
installed metadata files also become immutable under its ordinary route.
The adopted root toolchain and TypeScript config join the protected quality
inputs; changing those with a dependency upgrade is not the ordinary pair.

A compatible Stack update may change the single canonical root development pin
and its consistent registry lock, leaving commands, source/profile/config and
all frozen inputs unchanged. The existing dependency verifier binds base/head
install bytes, registry integrities and Ajv/YAML closure. V3 introduces no
current Stack or companion release literal. Synthetic dependency fixtures prove
only this source-binding route, not a future package's engine/API compatibility
or physical qualification. Normal frozen install and exact-head native CI remain
mandatory for every actual update.

## Reversible owner-only phases

The code expects these main context sets: the four unrelated checks plus v2;
those same checks plus v2 and v3; then the same checks plus v3. The unrelated
checks are `check`, `trusted-admission-evidence`,
`trusted-admission-authority-evolution-v1` and `trusted-validation`. Separate
`commit-author-identity`, App15368, strict current-base enforcement, PR rules,
no bypass and every unrelated protection field must remain unchanged. These
are expected contracts, not a fresh live owner-full observation.

1. Independently review the bound source and target. Before creating the source
   branch, establish and read back its exact repository-owned active
   update/deletion/non-fast-forward lock with no bypass. Only then create the
   dedicated `governance/quality-source-successor-v3` branch once, and
   obtain a genuine push qualification, source result and v3 status on the exact
   still-open target. Observe actual source SHA/tree/run/attempt and native CI.
2. Add v3 before removing v2, with complete owner-full readback after each step.
   The frozen v2 source accepts only its historical v1/v2 protection phases, so
   adding v3 can make v2 reject. This is an expected fail-closed bridge, never
   permission to forge green or remove unrelated checks. A pre-change v2 green
   does not observe the new protection phase: distinguish an expected refusal
   from an actual fresh defining run and retain both readbacks. V3 must genuinely pass
   the exact finite target before only its incompatible v2 predecessor is removed.
   Merge normally through the owner guard; verify final tree and full main CI.
3. To install the three-file v3 caller/decision/evidence under an already
   installed source, add v2 back before removing temporary v3, reading back both
   phases. V2 may reject the intermediate v2+v3 set and recover only after v3 is
   removed. Preserve its old caller, source and immutable installation evidence.
   Obtain genuine v2 ordinary acceptance and unrelated exact-head checks for
   the additive v3 installation; then merge normally. The earlier source push
   targeted the finite adoption PR and does not qualify this new installation PR.
4. With installed-main v3 optional and v2 still required, run real ordinary
   positive and protected-input negative canaries through the exact immutable
   v3 caller. Retain actual PR/base/head, source, run/attempt, decisive steps and
   statuses. Never merge the negative canary or treat optional rejection as
   required-check blocking proof.
5. Add v3 while retaining v2; read back fresh owner-full protections and prove
   on the same negative head that v3 failure is required and mergeability is
   blocked. Record the expected frozen-v2 bridge refusal separately. Only after
   positive success and that blocking proof may v2 be removed. Re-read all
   protections and genuine installed-main results after final cutover.
6. On failure, stop and retain/re-add the previous requirement before removing
   the new one. Preserve the old caller/source so genuine v2 results can resume
   after its supported protection set is restored. Reverting any installed
   files requires a separately reviewed normal PR; never mutate locked source,
   historical tuples or accepted evidence, and never leave a zero-source interval.

This worker performed none of these external phases. The proposal grants no
agent protection permissions, merge authority, deployment/adoption claim or
exception to independent review, exact-head CI, current protection observation
and the owner's real merge guard.
