The finite source push certified PR392 while it was open. PR392 is now closed;
that historical run cannot certify an installation PR or be replayed as one.
No installer PR/head, installed-main run, canary or blocking proof exists in
this snapshot. Source qualification does not invent those coordinates.

Install through the unchanged v2 ordinary route. First add old v2 alongside
currently required v3 and read back complete owner-full source/main/identity
protections. Only then remove temporary v3, preserving v2 and all unrelated
checks. Frozen v2 rejects the intermediate v2+v3 protection set; retain that
expected bridge refusal honestly. Require genuine old-v2 ordinary acceptance
and the unrelated exact-head checks for the actual additive installation PR,
then use the normal owner merge guard. Never forge a required context or leave
a zero-source interval.

After the caller is genuinely installed, obtain real ordinary positive and
protected-input negative canaries through its immutable S. Retain actual
PR/base/head, source/workflow/run/attempt, decisive jobs and statuses. An
optional v3 rejection proves rejection only. Add v3 while retaining v2 and
observe on that same negative head that v3 is required and mergeability is
blocked. Only after the genuine positive result and required blocking proof
may old v2 be removed for permanent cutover. Do not merge a negative canary.

## Rollback and limits

On failure stop and retain/re-add the old requirement before removing the new
one, with complete owner readbacks and all unrelated fields preserved. Do not
unlock, update or delete either immutable source, historical tuple or accepted
installation snapshot. File rollback requires a separately reviewed normal PR.

The local installation proof uses the actual merged M/tree and raw package/lock
bytes with a complete inert three-file envelope. It executes the real frozen
v2/v1 gates and source-owned caller assertion. It establishes route shape only;
the installation PR's complete native CI, installed-main canaries, required
blocking proof and permanent cutover remain pending. It changes no production
runtime, published architecture standard or Docs Cohort record.
