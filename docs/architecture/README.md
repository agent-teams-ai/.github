# Organization Architecture Standards

- [Feature Module Standard](feature-module-standard/README.md) - immutable
  baseline and repository-local adoption contract for feature-owned capability
  slices.

- [Foundation-first Architecture and ecosystem vision](ecosystem-vision.md) - maintained
  owner direction, repository responsibilities, planned consumers and delivery sequence;
  not a new immutable standard or product adoption.

- [Native and AOT readiness](../engineering-quality-standard.md#native-and-aot-readiness) -
  common practices for low-cost portability and real target qualification;
  [scoped delivery plan](native-readiness-plan.md) with owner follow-ups.

- [Evolution-ready architecture](evolution-readiness.md) - common authoring
  direction, conditional capability profiles, reuse owners and testable claims.

- [Reusable library delivery plan](evolution-library-delivery-plan.md) - proposed
  package placement, reuse checks, source-first testing and extraction triggers;
  no new repository or package is admitted by this guide.

- [Source-backed implementation priorities](https://github.com/agent-teams-ai/engineering-research/blob/main/docs/lessons/preimplementation-decisions.md) -
  competitor evidence and concrete follow-through in the owning repositories.

Use the [engineering quality baseline](../engineering-quality-standard.md) for
shared practices, then the target repository's accepted ADR, selected adoption
profile and implementation plan for binding decisions. Research supplies evidence;
these maintained organization guides do not supersede product owners or turn
conditional capabilities into mandatory work.
