# Security Policy

Do not report security vulnerabilities through public issues, discussions, pull
requests, logs, or example fixtures.

Use the target repository's **Security** tab and private vulnerability reporting.
Include the affected repository and version, impact, reproduction conditions,
and the smallest safe evidence needed to investigate. Remove credentials,
personal data, workspace content, and authority material from the report.

The organization-default issue chooser links to this policy because a shared
template cannot construct a repository-specific private-reporting URL. Always
return to the affected repository before submitting the report.

The owning repository defines supported versions and response expectations.
Security-sensitive fixes may follow an embargoed process and be published only
after affected users have a safe upgrade path.
